# CTF Writeup — Truncated LCG Lattice Recovery

**Category:** Cryptography  
**Techniques:** Linear Congruential Generator (LCG), lattice construction, LLL, Babai's nearest-plane algorithm, SHA-256 keystream recovery  
**Flag:** `ctf7{trunc4t3d_lcg_l4tt1c3_r3c0v3ry}`

## 1. Challenge Overview

The challenge provides a JSON file containing the parameters of a Linear Congruential Generator (LCG), several truncated outputs, and an encrypted flag.

The goal is to reconstruct the generator's hidden state from partial output leakage, derive the decryption key, and recover the flag.

Only the upper 24 bits of each 64-bit state are leaked. The lower 40 bits remain unknown. Recovering these missing bits independently would be difficult, but the states are related by a deterministic modular recurrence. These constraints make lattice-based recovery possible.

## 2. Understanding the Vulnerability

An LCG generates a sequence according to

\[
s_{i+1} = (a s_i + c) \bmod M
\]

where:

- \(s_i\) is the internal state at step \(i\).
- \(a\) is the multiplier.
- \(c\) is the increment.
- \(M\) is the modulus.

For this challenge, \(M=2^{64}\), and only the upper 24 bits of each state are exposed:

\[
y_i = \left\lfloor \frac{s_i}{2^{40}} \right\rfloor
\]

Thus, each state can be written as

\[
s_i = 2^{40} y_i + r_i,\qquad 0 \le r_i < 2^{40}
\]

The unknown low bits \(r_i\) are constrained by the LCG recurrence. All leaked outputs are therefore related, and the same initial state must explain every observation.

**Security lesson:** truncating outputs does not necessarily make a predictable generator cryptographically secure.

## 3. Expressing the Recurrence as an Affine Function

Expanding the recurrence gives

\[
s_i = (a^i s_0 + b_i) \bmod M
\]

where

\[
b_0=0,\qquad b_{i+1}=(a b_i+c)\bmod M
\]

Define

\[
p_i = a^i \bmod M
\]

Then

\[
s_i = (p_i s_0 + b_i) \bmod M
\]

The unknown seed \(s_0\) is shared by all observations. Instead of recovering each missing low-bit portion separately, the attack searches for one integer consistent with all the observations.

## 4. Constructing the Target Vector

The leaked value \(y_i\) tells us that the true state lies in the interval

\[
2^{40}y_i \le s_i < 2^{40}(y_i+1)
\]

The solver uses the midpoint of this interval as an approximation:

\[
t_i = 2^{40}y_i + 2^{39}
\]

Subtract the affine offset \(b_i\), modulo \(M\), to obtain the target coordinate:

\[
u_i = t_i-b_i \pmod M
\]

For numerical stability, values greater than \(M/2\) are represented as negative integers by subtracting \(M\). This centers the target coordinates around zero.

The target vector is

\[
u=(u_0,u_1,\ldots,u_{n-1})
\]

where \(n\) is the number of leaked outputs.

## 5. Lattice Construction

The solver constructs a lattice basis of the form

\[
B=
\begin{pmatrix}
1 & p_1 & p_2 & \cdots & p_{n-1}\\
0 & M & 0 & \cdots & 0\\
0 & 0 & M & \cdots & 0\\
\vdots & \vdots & \vdots & \ddots & \vdots\\
0 & 0 & 0 & \cdots & M
\end{pmatrix}
\]

A lattice vector generated by this basis has the form

\[
v=(x,\;p_1x+q_1M,\ldots,p_{n-1}x+q_{n-1}M)
\]

for integers \(x,q_1,\ldots,q_{n-1}\).

The first coordinate \(x\) is a candidate initial state. The remaining coordinates represent the corresponding modular sequence, with integer multiples of \(M\) accounting for modular wraparound.

The objective is to find a lattice vector close to the target vector \(u\). The true seed should produce a vector close to the midpoint estimates after the affine offsets have been removed.

## 6. LLL Basis Reduction

The Lenstra–Lenstra–Lovász (LLL) algorithm transforms the original basis into a shorter, more nearly orthogonal basis spanning the same lattice.

The solver uses SymPy:

```python
reduced = Matrix(rows).lll(
    delta=ZZ(3) / ZZ(4)
)
```

The reduction parameter \(\delta=3/4\) is a standard LLL setting.

LLL does not directly recover the seed. It improves the basis so that the subsequent closest-vector approximation is more effective.

## 7. Gram–Schmidt Orthogonalization and Babai's Algorithm

The `gso()` function computes the Gram–Schmidt orthogonalized basis vectors, projection coefficients, and squared norms.

For basis vectors \(b_i\), Gram–Schmidt produces orthogonalized vectors \(b_i^*\). These vectors allow the solver to estimate how much of each basis vector is needed to approximate the target.

The `babai()` function applies Babai's nearest-plane algorithm. It processes the reduced basis in reverse order, rounds projection coefficients to nearby integers, and subtracts the corresponding basis-vector contributions.

Conceptually, it approximates the closest-vector problem:

\[
\underset{v\in L}{\operatorname{minimize}}\ \|u-v\|
\]

where \(L\) is the lattice generated by \(B\).

Babai's algorithm is an approximation; it does not guarantee the globally closest lattice vector in every instance. The solver therefore validates the recovered candidate against the exact recurrence and all leaked outputs.

The candidate seed is extracted from the first coordinate of the lattice vector:

```python
state0 = lattice_vector[0] % M
```

## 8. Recovering and Verifying the State Sequence

Starting from the candidate seed, the solver regenerates the sequence:

```python
states = []
state = state0

for i, expected in enumerate(leaked):
    assert (state >> SHIFT) == expected, (
        i, state >> SHIFT, expected
    )
    states.append(state)
    state = (a * state + c) % M

state8 = state
```

The assertion checks that the upper bits of every recovered state match the corresponding leaked output exactly.

This is essential: a lattice vector that is merely close to the target is not enough. The candidate must reproduce all observed outputs.

The solver also verifies the recurrence for adjacent states and calculates the next state after the final leaked state.

## 9. Deriving the Decryption Key

The challenge uses the next LCG state as the input to a SHA-256-based keystream generator.

The state is encoded as an eight-byte big-endian value:

```python
key_bytes = state8.to_bytes(8, "big")
```

Recovered key bytes:

```text
1a664328ca81141c
```

For counter \(j\), the keystream block is

\[
K_j = \operatorname{SHA256}
\left(
\text{key\_bytes}\parallel\operatorname{BE32}(j)
\right)
\]

Here, \(\operatorname{BE32}(j)\) is a four-byte big-endian counter, starting at zero, and \(\parallel\) denotes byte concatenation.

The solver generates enough SHA-256 output to cover the ciphertext:

```python
keystream = bytearray()
counter = 0

while len(keystream) < len(ct):
    keystream.extend(
        hashlib.sha256(
            key_bytes + counter.to_bytes(4, "big")
        ).digest()
    )
    counter += 1
```

Each SHA-256 digest contributes 32 bytes. The counter is incremented until the keystream is long enough.

## 10. Decrypting the Ciphertext

The ciphertext is decrypted using bytewise XOR:

\[
P_i=C_i\oplus K_i
\]

where \(C_i\) is a ciphertext byte, \(K_i\) is the corresponding keystream byte, and \(P_i\) is the plaintext byte.

The solver performs the XOR and validates the expected flag format:

```python
plaintext = bytes(
    x ^ y for x, y in zip(ct, keystream)
)

flag = plaintext.decode()

assert flag.startswith("ctf7{")
assert flag.endswith("}")
```

Recovered plaintext:

```text
ctf7{trunc4t3d_lcg_l4tt1c3_r3c0v3ry}
```

## 11. Attack Workflow Summary

1. Parse the LCG parameters, leaked outputs, hidden-bit count, and ciphertext from `data.json`.
2. Compute the affine recurrence coefficients \(p_i\) and \(b_i\).
3. Build a centered target vector from the midpoint of each truncated-state interval.
4. Construct the lattice basis using the recurrence coefficients and modulus.
5. Reduce the basis with LLL.
6. Use Gram–Schmidt orthogonalization and Babai's nearest-plane algorithm to find a candidate lattice vector.
7. Extract the candidate initial state and regenerate the complete state sequence.
8. Verify that every leaked output matches exactly.
9. Compute the next LCG state and encode it as eight big-endian bytes.
10. Generate the SHA-256 keystream using a four-byte big-endian counter beginning at zero.
11. XOR the keystream with the ciphertext and validate the flag.

## 12. Why the Attack Works

The attack exploits three weaknesses:

1. **Predictable generator structure:** the LCG recurrence is linear modulo \(M\).
2. **Correlated leakage:** every truncated output constrains the same initial state.
3. **Predictable key derivation:** the encryption keystream depends directly on the next LCG state.

LLL makes the lattice basis more suitable for the closest-vector approximation. Babai's algorithm provides a candidate, and exact recurrence and leakage checks establish that the recovered sequence is consistent with the supplied observations.

This does not mean every truncated LCG can be solved using LLL and Babai. Success depends on the modulus, number of observations, amount of leakage, target construction, and lattice geometry.

## 13. Security Recommendations

For real cryptographic systems:

- Replace LCG-based key generation with a cryptographically secure pseudorandom number generator (CSPRNG).
- Never derive encryption keys from predictable or partially observable generator state.
- Use a standard key derivation function when transforming secret key material into encryption keys.
- Prefer authenticated encryption such as AES-GCM or ChaCha20-Poly1305.
- Do not assume that hiding low-order bits makes a non-cryptographic PRNG secure.
